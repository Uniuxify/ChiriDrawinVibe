# ChiriDrawin — план, требования и архитектура

## 1. Общее описание

ChiriDrawin — веб-приложение для коллаборативного рисования. Общий холст разбит на ячейки, распределённые между игроками. В рамках итерации игрок последовательно разблокирует и заполняет свои ячейки, видя контекст соседних уже заполненных ячеек в ограниченной зоне. Итоговая картина собирается из всех ячеек после завершения сессии.

Ключевые принципы:
- источник истины для рисунка — векторная JSON-история операций;
- растр генерируется сервером в момент фиксации ячейки и при сборке итоговой картины;
- синхронизация в MVP — периодический polling (интервал из конфига, по умолчанию 5 с);
- архитектура закладывает возможность добавления real-time, новых типов сеток и загрузки изображений.

## 2. Роли и права

| Возможность | Админ | Игрок | Зритель |
|---|---|---|---|
| Регистрация/вход | да | да | нет (не нужен) |
| Список своих сессий | да | да | нет |
| Просмотр публичных завершённых сессий | да | да | да |
| Создание/удаление/редактирование сессий | да | нет | нет |
| Запуск/досрочное завершение сессии | да | нет | нет |
| Добавление/удаление игроков | да | нет | нет |
| Пропуск игрока / засчитать за игрока | да | нет | нет |
| Разблокировка подтверждённой ячейки | да (только её владельцу) | нет | нет |
| Рисование в своих ячейках | да (если игрок) | да | нет |
| Просмотр всех ячеек активной сессии | да (в режиме админа) | нет | нет |
| Просмотр всех ячеек завершённой сессии | да | да (если игрок) | да (если публичная) |
| Переключение режима админ/пользователь | да | — | — |

Особенности:
- Режим админа — отдельный контекст доступа. В режиме пользователя сервер обращается с админом как с обычным игроком: не отдаёт чужие ячейки, не даёт создавать сессии.
- Игрок может участвовать в нескольких сессиях одновременно.
- Зрителям аккаунт не нужен.

## 3. Функциональные требования

### 3.1 Аутентификация
- Регистрация: никнейм + пароль (без email).
- Вход: никнейм + пароль.
- JWT access + refresh.
- Зрительский доступ к публичным завершённым сессиям — без токена.

### 3.2 Список сессий (залогиненный пользователь)
- Блок 1 (сверху): завершённые сессии, результат которых игрок ещё не видел.
- Блок 2: активные сессии, где пользователь — игрок.
- Блок 3: завершённые сессии, где пользователь — игрок и уже видел результат.
- Пустое состояние: «вы не состоите ни в одной сессии».
- Для админа в режиме админа — дополнительно список всех сессий системы с фильтрами по статусу/публичности.

### 3.3 Создание сессии (админ)
Параметры:
1. Размер холста: ширина × высота (100..10000 px).
2. Тип сетки: пока только прямоугольная.
3. Количество ячеек: столбцы × строки (2..100 по каждой оси).
4. Максимальное число игроков (в UI — «Max Players»).
5. Интервал разблокировки (например, 1 день). Минимум — 0: при интервале 0
   таймер не запускается, и очередная квота выдаётся только когда все игроки
   заполнили по `unlock_quota` ячеек в текущей итерации.
6. Количество разблокируемых ячеек за итерацию (по умолчанию 1).
7. Форма контекста: прямоугольник или круг.
8. Радиус контекста — слайдер 0..100%:
   - 0% — фигура совпадает с ячейкой (для квадрата это радиус `sqrt(2)/2`,
     для круга — `0.5`); центральная ячейка всегда белая;
   - 100% — фигура достигает соседних ячеек (радиус 1.5 в клетках);
   - значение линейно растёт от минимума (0%) до 1.5 в клетках (100%).
     Рядом со слайдером — интерактивный предпросмотр: сетка 3×3, все ячейки
     серые, белая `ContextShape` центрируется на центральной ячейке.
     Для совместимости со старыми сессиями режимы `min`/`max` остаются в
     модели, но не используются в UI.
9. Логика распределения ячеек: `random` или `min_adjacent`.
10. Публичность (публичная/приватная).
11. (future) `allow_image_upload`.

После создания — статус `draft`, генерируется код присоединения. Запуск — отдельное действие.

### 3.4 Присоединение к сессии
- Админ добавляет зарегистрированного пользователя по никнейму.
- Игрок присоединяется сам по коду, если сессия в статусе `draft` и он ещё не участник.
- Один пользователь не может присоединиться дважды.
- Присоединяться (и добавлять игроков админом) нельзя, когда в сессии уже
  `max_players` участников — ошибка 409 «This session is full.».
- При запуске сессии ячейки распределяются согласно выбранной стратегии.

### 3.5 Жизненный цикл сессии

Статусы: `draft` → `active` → `finished`; плюс `deleted`.

- `draft`: сессия создана, ячейки не распределены. Можно менять все параметры, добавлять/удалять игроков, присоединяться по коду.
  - Запуск возможен и при неполном составе (досрочный запуск) — с подтверждением
    на клиенте («Are you sure you want to start early?»); на бэке разрешается
    при `0 < current_players <= max_players`.
  - Если `current_players > max_players` (непредвиденный переполнение) —
    ошибка «The session has more players than allowed: X of Y.».
  - 0 игроков — ошибка «Not enough players joined: 0 of Y required.».
- `active`: ячейки распределены. Можно менять только список игроков (только удаление), интервал, квоту, публичность. Остальное зафиксировано.
- `finished`: сессия завершена (все ячейки заполнены или админ завершил вручную). Доступен просмотр результата и таймлапс.
- `deleted`: каскадное удаление всех связанных сущностей.

Досрочное завершение: незаполненные ячейки остаются пустыми (белый фон).

### 3.6 Итерации и разблокировка
- В начале итерации игроку доступна квота `unlock_quota` ячеек.
- Игрок выбирает одну из своих незаполненных ячеек и разблокирует её.
- В момент разблокировки:
  - ячейка блокируется для всех;
  - блокируются соседние ячейки, попадающие в зону контекста (по форме/радиусу);
  - игроку отдаётся снапшот контекста (растр соседних заполненных ячеек в зоне контекста);
  - если соседняя ячейка пустая — показывается область за голубой пунктирной линией с комментарием (если он был оставлен).
- Игрок последовательно разблокирует и заполняет ячейки в рамках итерации, пока не исчерпает квоту.
- Игрок не может разблокировать следующую ячейку, пока не подтвердил текущую.
- Старт рисования фиксируется по первому непустому автосохранению (ластик/выделение на пустой ячейке не считается).
- Итерация завершается, когда **все** игроки исчерпали квоту.
- Таймер итерации запускается, когда **первый** игрок исчерпал квоту.
- Если игрок не подтвердил и не начал рисовать — сессия ждёт бесконечно (без автотаймаута).
- Если игрок начал рисовать, но не подтвердил до конца интервала — автокоммит последнего состояния.
- Админ может: снять блокировку с ячейки (только её владельцу), «пропустить игрока» (ячейка уходит другому — случайному среди тех, у кого меньше всего собственных ячеек), «засчитать за игрока» (ячейка считается заполненной, но пустой).

### 3.7 Редактор рисования

Инструменты:
- кисть (выбор кисти, размера);
- ластик;
- заливка;
- палитра + пипетка;
- фигуры (прямоугольник, эллипс, линия и т.п.);
- выделение;
- undo (Ctrl+Z), redo (Ctrl+Y) — **только на клиенте**.

Особенности:
- Холст ячейки + видимая read-only зона контекста.
- Автосохранение промежуточной истории на сервер с интервалом при изменениях.
- Финальный коммит — кнопка «Подтвердить» с диалогом о необратимости.
- После коммита ячейка read-only.
- Комментарий: одно необязательное поле, отправляется при коммите. Один комментарий на ячейку. Не входит в историю/таймлапс, показывается при наведении на область контекста.
- Валидация на бэке: число операций в истории — в допустимых пределах (лимит конфигурируемый).

### 3.8 Экран холста сессии

Активная сессия (игрок):
- Холст; чужие незавершённые ячейки — чёрные.
- Свои заполненные — видны; свои незаполненные — серые.
- Контекст, полученный при разблокировке, — виден.
- При наведении на свою ячейку — голубой border.
- Иконка замка на своих ячейках; если доступна разблокировка — замок с ключом.
- Клик → подтверждение → ячейка белая → двойной клик открывает редактор.
- Индикаторы: время до разблокировки, число доступных разблокировок, процент завершённости холста.
- Кнопка «назад» слева сверху.
- Для админа: кнопка «раскрыть ячейки» + переключатель режима админ/пользователь слева снизу. В режиме админа сверху по центру красным «Administrator Mode».

Завершённая сессия:
- Первый вход — модалка «Игра завершена!» с кнопкой «Смотреть результат».
- Холст с закрытыми ячейками; клик по ячейке открывает её содержимое (постепенное раскрытие).
- Доступен таймлапс.

### 3.9 Просмотр зрителем
- Список публичных завершённых сессий без авторизации.
- Экран просмотра: холст с закрытыми ячейками, раскрытие кликом, таймлапс.

### 3.10 «Осиротевшие» ячейки
- При удалении игрока его незаполненные ячейки не раздаются сразу.
- Хранятся отдельно и распределяются между оставшимися игроками только после того, как все «изначально закреплённые» ячейки заполнены.
- Распределение равномерное (насколько возможно при неделимости), случайное.
- То же — при пропуске игрока или выходе без возврата.

## 4. Доменная модель

- **User** — `id`, `username` (unique), `password_hash`, `is_admin`.
- **Session** — `id`, `name`, `status`, `owner_id`, `join_code`, `canvas_width`, `canvas_height`, `grid_cols`, `grid_rows`, `players_count`, `interval_seconds`, `unlock_quota`, `context_shape`, `context_radius_pct`, `distribution_strategy`, `is_public`, `created_at`, `started_at`, `finished_at`, `allow_image_upload` (future).
- **SessionPlayer** — `session_id`, `user_id`, `joined_at`, `is_active`.
- **Cell** — `id`, `session_id`, `row`, `col`, `owner_id`, `status` (`empty` / `unlocked` / `filled` / `orphan`), `locked_by_user_id`, `unlocked_at`, `filled_at`, `comment`.
- **CellHistory** — `id`, `cell_id`, `revision`, `operations_json` (JSONB), `is_final`, `created_at`.
- **CellRaster** — `id`, `cell_id`, `s3_key`, `width`, `height`, `created_at`.
- **CellContextSnapshot** — `id`, `cell_id`, `s3_key`, `neighbor_rasters_json`, `created_at`.
- **Iteration** — `id`, `session_id`, `index`, `started_at`, `finished_at`, `state`.
- **OrphanCellPool** — либо флаг в `Cell`, либо отдельная таблица.
- **CellView** — `user_id`, `session_id`, `cell_id`, `viewed_at` (для «уже видел результат»).

Хранение:
- PostgreSQL, JSONB для операций и метаданных.
- MinIO (S3) для растров, снапшотов, таймлапсов.

## 5. Формат истории и рендер

### 5.1 История
JSON-массив операций:
```json
{
  "type": "stroke" | "fill" | "shape" | "erase" | "clear",
  "ts": 1234567890,
  "tool": "brush" | "eraser" | "rect" | "ellipse" | "line",
  "color": "#RRGGBBAA",
  "size": 4,
  "points": [[x, y], ...],
  "shape": { "x": 10, "y": 10, "w": 100, "h": 50 },
  "meta": {}
}
```
Координаты нормализованы в системе ячейки (0..cell_width, 0..cell_height).

Валидация:
- лимит числа операций на ячейку (конфигурируемый);
- лимит суммарного размера JSON на ячейку;
- проверка корректности координат и типов.

### 5.2 Пайплайн рендера
- Клиент → JSON-история → сервер.
- Сервер: JSON → SVG → растр (**CairoSVG** в MVP).
- Растр сохраняется в MinIO, ключ привязан к ячейке.
- Рендер выполняется при:
  - финальном коммите ячейки;
  - завершении сессии (сборка общей картины).

### 5.3 Таймлапс
- Данные — упорядоченная история операций с таймстампами.
- Проигрывается на клиенте (Konva + анимация по таймлайну).

## 7. Frontend-архитектура

Стек:
- React 18 + TypeScript + Vite
- react-router-dom
- TanStack Query (запросы + polling, интервал из конфига, по умолчанию 5 с)
- Zustand (локальное состояние редактора)
- **MUI** (UI-компоненты)
- Konva + react-konva (холст, слои, фигуры, future images)

Структура:
```
src/
  app/            # роутинг, провайдеры, конфиг
  api/            # клиенты REST, DTO
  features/
    auth/
    sessions/
      list/
      create/
      detail/
    editor/
      canvas/
      tools/
      history/    # undo/redo (клиентское)
      autosave/
    viewer/       # просмотр завершённой сессии + таймлапс
  shared/
    ui/
    lib/
    config/
  store/          # Zustand-сторы
```

Ключевые компоненты:
- `SessionCanvas` — сетка, статусы ячеек, контекст.
- `CellEditor` — редактор с инструментами, undo/redo, автосохранением.
- `ContextOverlay` — read-only слой контекста с тултипами комментариев.
- `SessionAdminPanel` — управление сессией.
- `SessionResultView` — раскрытие ячеек по клику + таймлапс.

## 8. Backend-архитектура

Стек:
- Django + DRF
- PostgreSQL + JSONB
- MinIO (S3)
- Celery + Redis — рендер растров, сборка общей картины, распределение «осиротевших» ячеек
- JWT (djangorestframework-simplejwt)
- CairoSVG для рендера (с возможностью замены на Playwright через `RENDERER`)

Django-приложения:
```
apps/
  accounts/        # пользователи, аутентификация
  sessions/        # сессии, игроки, итерации
  cells/           # ячейки, истории, растры, снапшоты, комментарии
  rendering/       # JSON → SVG → растр, таймлапс-данные
  admin_api/       # эндпоинты для админа
  common/          # утилиты, permissions, pagination, validators
```

Ключевые сервисы:
- `CellDistributionService` — распределение ячеек (random / min_adjacent), перераспределение «осиротевших».
- `SessionLifecycleService` — старт, завершение, досрочное завершение.
- `IterationService` — итерации, таймеры, квоты.
- `LockService` — блокировки ячейки и соседей по зоне контекста.
- `ContextService` — снапшот контекста.
- `RenderService` — JSON → SVG → растр (CairoSVG).
- `PermissionService` — матрица доступа с учётом режима админ/пользователь.
- `ValidationService` — лимиты холста, сетки, истории, размеров JSON.

## 9. Валидация и лимиты

На бэке:
- `canvas_width`, `canvas_height`: 100..10000 px.
- `grid_cols`, `grid_rows`: 2..100.
- Максимум операций в истории ячейки — конфигурируемый лимит.
- Максимальный размер JSON-истории на ячейку — конфигурируемый лимит.
- Проверка координат/типов операций.
- Проверка `unlock_quota` ≥ 1.
- Проверка `interval_seconds` ≥ 0 (0 = без таймера, ждём всех игроков).

Публичный конфиг отдаётся фронту через `GET /api/v1/config`.

## 11. Особые случаи (чек-лист)

- [ ] Игрок не может редактировать после коммита.
- [ ] Зона контекста read-only.
- [ ] Блокировка соседей по форме/радиусу контекста (не всегда 8).
- [ ] Игрок не может разблокировать вторую ячейку, пока не закончил с первой.
- [ ] Сессия ждёт игрока бесконечно (без автотаймаута).
- [ ] Автокоммит при истечении интервала, если начато рисование.
- [ ] Админ: разблокировка, пропуск, форс-заполнение.
- [ ] «Осиротевшие» ячейки — отдельный пул, раздаётся после заполнения «родных».
- [ ] Досрочное завершение: пустые ячейки = белые.
- [ ] Просмотр завершённой сессии: постепенное раскрытие.
- [ ] Модалка «Игра завершена!» при первом входе.
- [ ] Зритель без авторизации видит только публичные завершённые.

## 12. Задел под будущие фичи

1. **Загрузка изображений**
   - В JSON-историю добавляется тип операции `image` со ссылкой на S3-объект и трансформацией.
   - Флаг `allow_image_upload` уже в модели сессии.
   - Konva поддерживает `Konva.Image` и трансформации.

2. **Новые типы сеток**
   - `grid_type` в модели сессии.
   - `Cell` хранит `row`, `col`; для новых типов — `geometry` JSONB и, при необходимости, `polygon` для рендера и хит-тестов.
   - `LockService` и `ContextService` работают через интерфейс `NeighborResolver`, а не жёстко 8 клеток.

3. **Real-time**
   - REST остаётся; добавляется Django Channels + Redis, дублирующий события `cell_unlocked`, `cell_committed`, `iteration_finished`.
   - Фронт при наличии WS отключает polling.
